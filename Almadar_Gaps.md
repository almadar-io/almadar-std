- **G-STD-082** — A RESP-in-`.lolo` port of `std-redis` (over `os/tcp-connect|send|recv|close`, spec `spec/store/redis.lolo`, 218 replica checks) is PARKED at `~/.almadar/parked/std-redis.lolo.resp-wip` and `std-redis` stays on the kernel driver, because the port dropped features: concurrent calls (needs the approved keyed instances), TLS, the credential store, and safe non-UTF-8 handling. The four substrate holes that cost it parity with the kernel `redis` driver (`orbital-rust/.../runtime/src/redis.rs`). (1) No byte-validity test: `bytes/to-string` throws on invalid UTF-8 and `base64/valid` takes `string`, not `bytes`, so a non-UTF-8 bulk or reply line (spec: unsupported) throws inside the decode transition and the call stays in `decoding` with the socket open; needs `bytes/valid-utf8` (orbital-core + `modules/bytes.ts`). (2) No credential read: a `secret` knob is readable only as an `http` `auth` slot (`ORB_SECRET_OUTSIDE_AUTH`), so the AUTH password comes from `os/getenv` named by the `passwordEnv` knob (needs an `env` grant), skipping the encrypted credential store and user-scoped credentials. (3) `os/tcp-connect` has no TLS option, so `tls: true` (was `rediss://`) answers `REDIS_FAILED` unsupported. (4) `os/tcp-connect` host and port must be static (`ORB_OS_TARGET_NOT_STATIC`), so the `origin` knob became `host`/`port`/`tls`, and the egress refusal is the host's `denied` rather than a refusal before any ask (the password `os/getenv` runs first). RESP3 frames are not decoded (the atom never sends `HELLO`). `@almadar/std` + `orbital-core` [architectural] — found by the S23 port; prevention rung: `.lolo` types (a `bytes` UTF-8 test) / `orb validate`.
