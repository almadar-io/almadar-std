std-lolo-source — renders .lolo source as native code in any target language, with every spelling of the language in config. LOLO_TO_SOURCE { source, path? } answers SOURCE_RENDERED { text, warnings }, or SOURCE_RENDER_FAILED { error } when the source cannot be read, the installed operator table is not readable, a render is already running, or the target needs the checker's types (requiresTypes) and the request carries no path. The output never calls the kernel and gives the kernel's answers. 
Pipeline: it reads the installed operator table once per request (the file @almadar/std declares as orbLanguage.operators, for the operator names only), reads the program with program/read, collects the containers and the traits, renders every guard, effect and default with tree/fold, and assembles imports, helpers and one class per trait. A list is a call exactly when its first item is a string naming an operator of that table (a form included: fn, let, if, do, set, emit, render-ui, when) or match or invoke; any other list is a list literal. 
Templates are strings with {{key}} placeholders filled in one pass, so text that looks like a placeholder inside a program string is never filled twice. A call takes the first of: the lambda template (lambdaOperators, when the second argument is an fn), the unary template (one argument), the infix symbol (two or more arguments), operators[op#N] (exactly N arguments), operators[op], the callee (callees). An operator no table covers is the unsupported form, which must raise when run, plus the warning unsupportedWarn: the output never calls a name it does not define. helpers keys an operator or token to the definitions it needs; each used definition is written once, sorted. imports keys an operator or token to its import line. 
An effect listed in portEffects is called on the ports object (portCall) and each is a warning that names the site (Trait.EVENT). render-ui is a comment. emit builds the payload as the shell's generated payload type (payloadType names it like the TypeScript shell, <Trait><EVENT>Payload) and the entity and payload types are imported (modelImports) unless renderModels is true, which writes the entities and type aliases as model code. set is an assignment, or with setStyle copy a rebuilt entity (one field deep; a deeper path warns). entityReadDefault, when set, reads a defaulted entity field with a scalar or empty default as coalesce(field, default). 
Types: with the original absolute path of the .lolo file the reader answers the kernel checker's type of every node (program/read with inspect) by ir-path. {{type}} in an operator template is the type of the call, {{type0}}, {{type1}}... the types of its arguments, and {{type}} in letStmt and letExpr the type of the bound value; each is typeNames[type text] when listed, else the checker's text, else typeUnknown. The atom infers no type itself. A typed target sets requiresTypes. 
Literals: stringEscapes adds target-specific replacements inside every string literal (sorted key order, quotes untouched); numberIntForm writes a number whose JSON text is an integer and numberForm writes any other. A map literal with no pair is mapEmpty when set. entityNames renames the .lolo entity wherever its name is written, payloadFieldOrder sorted lists payload fields by name, and fileHeader is written before the imports.
Known limits: a let binding named like an operator (path, list, log...) adds a spurious unsupported or port warning for the binding; entityReadDefault covers scalar and empty-collection defaults only; a fn body renders its last expression only.
